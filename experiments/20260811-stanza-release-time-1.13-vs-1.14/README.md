# Stanza 1.13.0 vs 1.14.0: release-time Slovenian models

Run stamp `20260811-stanza-release-time-1.13-vs-1.14` · CJVT GPU server · 2026-08-11

## Purpose

This experiment reconstructs the **Slovenian resource/model configurations and
artifacts that Stanza 1.13.0 and 1.14.0 resolved to at their respective release
times**, then evaluates both releases on the same aligned UD Slovenian **SSJ**
(written) and **SST** (spoken) test sets with `default` and
`default_accurate`.

It is the historical follow-up to the original
[`20260810-stanza-1.13-vs-1.14-ssj`](../20260810-stanza-1.13-vs-1.14-ssj/)
and
[`20260810-stanza-1.13-vs-1.14-sst`](../20260810-stanza-1.13-vs-1.14-sst/)
experiments. Those earlier runs are preserved unchanged.

## Why the reconstruction was necessary

The versioned Stanza resource files are mutable. The original 2026-08-10 run
showed that a present-day Stanza 1.13 installation resolves Slovenian
`default` / `default_accurate` to later `combined_*` models rather than the
`ssj_*` models that 1.13.0 resolved to at release time.

The full upstream chronology is documented in
[`references/stanza-1.13-vs-1.14-model-provenance.md`](../../references/stanza-1.13-vs-1.14-model-provenance.md).

## Dataset and evaluation design

Both treebanks are evaluated with **gold sentence and token boundaries**.
Stanza predicts `LEMMA`, `UPOS`, `XPOS`, `FEATS`, `HEAD` and `DEPREL`; gold
`ID`, `FORM` and `MISC` are preserved. Tokenisation quality is therefore outside
the scope of this experiment.

- **SSJ:** 1,282 sentences,
  25,442 syntactic words,
  SHA-256 `c14d5d2f4f20a7ad43e0f598a2e18c5e41f08364ab36be1c87d6d9eae7f5c8b0`.
- **SST:** 432 sentences,
  11,443 syntactic words,
  SHA-256 `6824234edf98cbbedb2e981644c324a3058c2920ed6cdcd7f467e835cfe25eeb`. The r2.16 and r2.17 copies of this
  test file are byte-identical; this experiment must not be silently migrated
  to r2.18.

The evaluator's `Sentences`, `Tokens` and `Words` scores are 100.00 by
construction and serve as alignment/integrity checks rather than quality
metrics.

## Main release-to-release result

| Test set | Package | 1.13.0 release LAS | 1.14.0 release LAS | Delta |
|---|---|---:|---:|---:|
| SSJ | `default` | 90.55 | 90.73 | +0.18 |
| SSJ | `default_accurate` | 95.04 | 94.86 | -0.18 |
| SST | `default` | 68.90 | 81.95 | +13.05 |
| SST | `default_accurate` | 78.33 | 86.13 | +7.80 |

On **SSJ**, release-to-release changes are small and mixed. On **SST**, the
1.14.0 release produces much higher scores, especially for dependency parsing
and the morphosyntax-sensitive composite metrics.

For all metrics and all three explicitly separated comparisons, see
[`comparison.txt`](comparison.txt), generated by
[`scripts/compare_stanza_release_time.py`](../../scripts/compare_stanza_release_time.py).

In `comparison.txt`, the short label `accurate` denotes Stanza's
`default_accurate` package.

The three comparisons are:

1. **Release-time 1.13 -> release-time 1.14** — the primary historical
   release-to-release comparison.
2. **Release-time 1.13 -> present-day-resource 1.13** — the effect of the
   post-release resource/model-set change while keeping the Stanza library at
   1.13.0.
3. **Present-day-resource 1.13 -> 1.14** — what the original 2026-08-10
   experiment measured. This is not a pure library-only comparison because the
   lemmatizer checkpoints differ between its two arms.

No statistical significance testing was performed.

## Verification of the 1.14 side

The reconstructed release-time Stanza 1.14 outputs were compared directly with
the original 2026-08-10 Stanza 1.14 outputs.

**All four prediction files are byte-identical, and all four evaluator output
files are byte-identical** for SSJ/SST x `default`/`default_accurate`.

Thus, for these aligned evaluations, the original Stanza 1.14 artifacts and the
reconstructed release-time 1.14 artifacts produce identical prediction and
evaluation files. The historical resource-resolution issue affecting the
original comparison was on the Stanza 1.13 side.

The reconstruction pins the **release-time Slovenian Stanza resource/model
configuration and artifacts under Stanza 1.13.0 and 1.14.0**. It does **not**
claim to recreate a bit-for-bit copy of the operating-system/CUDA environment
of the June/July 2026 release dates.

Model binaries and the historical `resources.json` files are not committed to
the repository. Their hashes and exact historical resource commits are recorded
in [`model-artifacts.json`](model-artifacts.json) and
[`manifest.json`](manifest.json).

## Reproducibility and QA

The experiment manifest was generated only after the following checks passed:

- both gold files matched their expected SHA-256;
- every required historical Stanza model artifact matched the MD5 declared by
  its pinned `resources.json`;
- the external transformer revision was pinned and evaluated offline;
- all eight release-time evaluations reported 100.00 for
  `Sentences` / `Tokens` / `Words`;
- all four reconstructed 1.14 predictions and evaluator outputs were
  byte-identical to the original 1.14 artifacts;
- `comparison.txt` was regenerated from the evaluator files and verified
  byte-for-byte.

## Limitations

- No statistical significance testing was performed.
- There is one evaluation run per condition; no new stochastic-stability study
  was performed.
- Gold token boundaries mean tokenisation quality is not evaluated.
- This is a historical **model/resource reconstruction**, not a complete
  historical machine-image reconstruction.
