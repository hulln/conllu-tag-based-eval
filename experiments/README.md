# experiments/

Human-written documentation and provenance for each evaluation experiment in
this repository. One directory per run stamp.

## Where things live

| Directory | Contents |
|---|---|
| [`experiments/`](.) | **human-written** experiment documentation and provenance — what was run, why, how, and with what environment |
| [`predictions/output/`](../predictions/output/) | **generated** model predictions (CoNLL-U) |
| [`results/output/`](../results/output/) | **generated** evaluation and analysis results |
| [`scripts/`](../scripts/) | reusable code — prediction, evaluation, QA, analysis, table building |
| [`docker/`](../docker/) | reusable container build files and generic container documentation |
| [`references/`](../references/) | cross-run, dataset-level and external material, plus the repository-level canonical manifest |
| [`data/`](../data/) | gold and raw input data (gold is local-only / gitignored) |
| [`tables/`](../tables/) | the published interactive comparison tables |

Nothing under `predictions/output/` or `results/output/` is written by hand; it
is produced by the scripts and should only ever be regenerated, never edited.

## Naming

```
stamp   = YYYYMMDD-HHMM[-<tag>]              e.g. 20260622-0810-tk13
run_id  = <stamp>_<dataset-tag>_<label>      e.g. 20260622-0810-tk13_sl-ssj-ud-test_full
```

One stamp can produce several run directories — one per dataset. The experiment
directory is named after the stamp and documents all of them.

`20260810-stanza-1.13-vs-1.14` predates this rule and uses a long descriptive tag
with no time component. It is left as it is, because the stamp is embedded in the
run directory name, four prediction filenames and the pinned manifest paths. New
runs should follow the grammar above.

Generated artifacts follow from the `run_id`:

- `predictions/output/<run_id>_<system>_<mode>_predicted.conllu`
- `results/output/<run_id>/main/<system>_<mode>_eval.txt`
- `results/output/<run_id>/main/<A>-vs-<B>_<mode>_comparison.md`
- `results/output/<run_id>/main/qa_validation.md`
- `results/output/<run_id>/diagnostics/<system>_<mode>_{eval-tagged.txt,errors.md}`

Runs driven by [`scripts/run_pipeline.py`](../scripts/run_pipeline.py) get their
`qa_validation.md` generated by [`scripts/qa_validate_run.py`](../scripts/qa_validate_run.py).
A run outside that contract must instead carry a **Verification** section in its
experiment README stating what was checked.

## What belongs in an experiment directory

```
experiments/<stamp>/
├── README.md          purpose, method, conditions, environment, commands,
│                      provenance, verification, limitations, links to outputs
├── manifest.json      optional: machine-readable provenance and file hashes
└── environment/       optional: pip-freeze or other environment snapshots
```

The README explains **how and why**; the detailed findings stay in
`results/output/`. Do not copy result tables or token-level listings into an
experiment README — link to them.

All runs use aligned mode: gold sentence and token boundaries are fixed, and the
systems predict lemma, POS/morphology and dependency annotation on top of that
fixed structure.

Superseded trial runs (`20260604-0837-tk13`, `20260604-0843-tk13`) are kept
locally but excluded from Git by [`.gitignore`](../.gitignore); they have no
experiment directory.
